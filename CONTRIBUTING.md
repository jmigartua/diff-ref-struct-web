# Contributing to diff-ref-struct Web

Thank you for wanting to help. The most useful contributions are reports: a bug with the steps that show it, a
feature with the analysis it would serve.

- **A bug**: the [bug form](../../issues/new?template=bug.yml). From the app, **Help ▾ ▸ Report a problem…** fills in
  the version, the browser and the view's address. A description and the address are enough: never attach
  unpublished data.
- **A feature**: the [feature form](../../issues/new?template=feature.yml): what you want to do, with which data, and
  what you do today instead. Requests are read, answered, and the ones taken up enter the roadmap (in the guide); the
  release that does one names it.
- **Code**: this repository is published from the project's own repository at each release, so a pull request here
  cannot be merged as it is. Open an issue first and describe the change; if it is taken up, it is made in the
  project and credited to you in the release notes.
- **Rules of the code**: every number is the core's (the page computes nothing); a claim carries its evidence (a test,
  a reference program's result); nothing is built on an unexplained difference with FullProf or GSAS-II.
